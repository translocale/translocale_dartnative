# TransLocale for DartNative

ARB localization and approved translation updates for native iOS and Android apps built with [DartNative](https://dartnative.com/).

- Bundle translations for the first launch and offline use.
- Switch languages, interpolate placeholders, and format ICU plurals and selects.
- Apply compatible wording releases from [TransLocale](https://translocale.io/) with a read-only delivery token.
- Restore validated updates from native app storage and pause polling in the background.

[Quick start](#quick-start) · [Live updates](#live-updates) · [Example](https://github.com/translocale/translocale_dartnative/tree/main/example) · [Issues](https://github.com/translocale/translocale_dartnative/issues)

## Requirements

Use the DartNative SDK with Dart `3.12.0-192.0.dev` or later. This package targets iOS and Android and uses `dartnative_system` for the installed app version and `dartnative_path_provider` for private cache storage. Android requires API 26 or later. Follow the SDK's platform requirements; Xcode 27 requires an iOS deployment target of at least 15 for the example and its pods.

The delivery protocol is shared with our Flutter packages. The widget integration uses DartNative's `App`, native text views, and lifecycle APIs. It provides key-based translations; Flutter's `gen-l10n`, localization delegates, and generated typed getters are not part of this package.

## Quick start

### 1. Install

Add the dependency to your app's existing `pubspec.yaml`:

```yaml
dependencies:
  dartnative_system: ^1.0.0
  dartnative_path_provider: ^1.0.0
  translocale_dartnative:
    hosted: https://dartpub.dev
    version: ^0.1.0
```

Then run:

```sh
dn pub get
```

Keep your existing DartNative framework dependencies. Declare `dartnative_system` and `dartnative_path_provider` directly in the app: dartpub removes closed SDK dependencies from hosted package manifests, so the app must select these native plugins explicitly. The shared `translocale_delivery` dependency comes from pub.dev. Use `dn pub get` so the SDK can resolve native packages.

### 2. Add bundled translations

Create `l10n/app_en.arb`:

```json
{
  "@@locale": "en",
  "hello": "Hello, {name}!",
  "@hello": { "placeholders": { "name": { "type": "String" } } },
  "items": "{count, plural, one {One entry} other {{count} entries}}",
  "@items": { "placeholders": { "count": { "type": "int" } } }
}
```

Create `l10n/app_fr.arb`:

```json
{
  "@@locale": "fr",
  "hello": "Bonjour, {name} !",
  "items": "{count, plural, one {Une note} other {{count} notes}}"
}
```

Create `tool/bundle.dart`:

```dart
import 'package:translocale_dartnative/bundle.dart';

void main(List<String> arguments) => runBundleCommand(arguments);
```

Generate the bundle with the **Dart executable supplied by DartNative**:

```sh
dart --packages=.dart_tool/package_config.json tool/bundle.dart \
  --arb-dir l10n --source en --catalog app.arb
```

This reads local files only. `app.arb` is the catalog identity used in TransLocale. The command writes `lib/translocale_bundle.g.dart`; commit it with your ARB files. It never starts a translation job.

After editing ARB files, regenerate with `--replace`. Use `--check` in CI to fail on a stale bundle without writing files. Do not format the generated file. The explicit package configuration avoids re-running the ordinary pub resolver against DartNative's SDK packages.

### 3. Use translations

Keep the plugin registration generated by `dn pub get`:

```dart
import 'package:dartnative/dartnative.dart';
import 'package:translocale_dartnative/translocale_dartnative.dart';
import 'dartnative_plugin_registrant.dart';
import 'translocale_bundle.g.dart';

void main() {
  DartNativePluginRegistrant.registerAll();
  final translations = TransLocale(catalog: translocaleCatalog, locale: 'en');
  runApp(App(
    title: 'My app',
    home: TransLocaleBuilder(
      translations: translations,
      builder: (context, t) => Scaffold(
        body: SafeArea(
          child: Column(children: [
            const TransLocaleText('hello', arguments: {'name': 'Sam'}),
            const TransLocaleText('items', arguments: {'count': 3}),
            Button(
              onPressed: () => t.setLocale('fr'),
              child: const Text('Français'),
            ),
          ]),
        ),
      ),
    ),
  ));
}
```

Create the controller once, outside `build`. `TransLocaleBuilder` owns and disposes it; do not share a controller between builders. Place the builder inside `App`, above the screens that use translations.

Use `TransLocaleScope.of(context)` in descendants, or `t.text('hello', arguments: {'name': 'Sam'})` when you need a string. `TransLocaleText` also supplies explicit native text direction and alignment, including right-to-left languages. You can override its `textAlign`, style, maximum lines, and overflow.

The app selects its locale explicitly. A request for `fr-CA` resolves to bundled `fr-CA`, then `fr`, then the source locale. Underscores are normalized. Keep every supported language in the bundle; updates cannot add languages or keys to an installed app.

## Live updates

Bundled localization works without an account. Live updates need a TransLocale project, an approved published release, and a read-only delivery credential scoped to the same project, channel, and schema.

### Match the app schema

Install the development CLI with Node.js 22.16 or later:

```sh
npm install --save-dev @translocale/cli@^0.5.1
```

Create `release-schema.json` in the app directory:

```json
{
  "sourceLocale": "en",
  "locales": ["fr"],
  "catalogs": [{ "file": "app.arb", "format": "arb", "path": "l10n/app_en.arb" }]
}
```

Run this local check and keep the returned `schemaHash` with the app build:

```sh
npx translocale release-schema --file release-schema.json
```

Use exactly the same source ARB, catalog identity, placeholder contract, and target languages when creating the release in the dashboard. Publish approved wording to `preview` first. Create a delivery credential for that schema and channel in the project's delivery settings. Recompute the schema after changing the app's source keys, placeholders, or languages.

### Connect the runtime

Add a delivery instance when creating your controller:

```dart
final translations = TransLocale(
  catalog: translocaleCatalog,
  locale: 'fr',
  delivery: DartNativeDelivery(
    projectId: const String.fromEnvironment('DELIVERY_PROJECT'),
    schemaHash: const String.fromEnvironment('DELIVERY_SCHEMA'),
    token: const String.fromEnvironment('DELIVERY_TOKEN'),
    channel: 'preview',
  ),
);
```

Supply those values with `dn run --dart-define-from-file=translocale.delivery.json`. Add `translocale.delivery*.json` to `.gitignore` before saving the settings. `DELIVERY_SCHEMA` must be the hash from the schema command, not a sample value.

The `tld_` token is included in the app and can be extracted. It grants read-only delivery access. Keep authoring credentials in the dashboard, development tools, or CI. Installation, bundle generation, schema checks, and delivery requests do not start paid translation jobs.

The builder shows bundled wording immediately, starts delivery after the first frame, and pauses automatic polling when the app leaves the foreground. Polling defaults to five minutes. Compatible snapshots are checked by the shared delivery client and stored under the app's private support directory. Network failures keep the last validated wording available.

### Configuration

| Option | Default | Purpose |
| --- | --- | --- |
| `projectId`, `schemaHash`, `token` | Required | Select the project and compatible release scope |
| `channel` | `production` | Use `preview` while testing |
| `apiBaseUrl` | `https://translocale.io` | HTTPS service origin; loopback HTTP is allowed for local tests |
| `appVersion` | Installed app version | Override automatic version detection when needed |
| `persistentCache` | `true` | Restore validated snapshots after restart |
| `cache` | Native file cache | Supply a custom `DeliveryCache` |
| `pollInterval` | Five minutes | Automatic refresh, from 30 seconds to one hour |

Use `await t.check()` for an explicit refresh and inspect `t.state.status`, `source`, and `error` for diagnostics. With `automaticUpdates: false`, the builder leaves polling inactive; the app may still call `start()` or `check()` explicitly. Standalone controllers need explicit startup, foreground/background handling through `setActive`, and disposal.

## Message support and fallback

This version supports one catalog per controller, up to 200 source messages, and ten target languages. Each ARB file must contain `@@locale` and be at most 100 KB. Metadata such as `@hello` is kept in the source ARB for schema checks but is not bundled as display text.

Messages support placeholders, `select`, and cardinal plurals with `zero`, `one`, `two`, `few`, `many`, and `other` branches. The formatter accepts `=0`, `=1`, and `=2`; use the category names for portability. Ordinals, plural offsets, other exact-number branches, rich text, and inline date/number format directives are unsupported. Use raw values in `arguments` for selectors. For app-specific date or number presentation, pass the corresponding string in `formatted` as well. This package does not generate formatting code from ARB metadata.

For each key, resolution tries delivered wording for the resolved language, bundled wording for that language, and bundled source wording. Unusable messages fall through to the next option. An unknown key returns the key itself or the supplied `fallback`. New keys, languages, layouts, and code require a new app build.

## Troubleshooting

- **Native packages fail to resolve:** run `dn pub get`. A `pubspec_overrides.yaml` containing `dependency_overrides` can mask overrides inserted by some SDK editions; remove development-only overrides for a registry installation.
- **The UI shows bundled wording:** inspect `t.state.error` and confirm the project, channel, schema hash, delivery token, and installed version match a published release.
- **`app_version` error:** keep native plugin registration, or supply `appVersion` explicitly. Lookup failures time out after three seconds and can be retried with `check()`.
- **Arabic text stays left aligned:** use `TransLocaleText`, or set both direction and alignment on your native `Text` view.
- **`Bundle is stale`:** regenerate with `--replace` and review the changed Dart file.
